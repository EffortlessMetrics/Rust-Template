## 2024-06-28 - ARIA states in Maud templates
**Learning:** Maud templates (`html!`) cannot use dynamic boolean attributes easily via string interpolation if they need to evaluate conditionally at runtime inside embedded Javascript logic. However, static setup for initial state (like `aria-pressed="true"` for default filters) and updating state via vanilla JS (`setAttribute('aria-pressed', 'true')`) works well for filter button groups, establishing a clear semantic state for screen readers. In addition, when elements like inputs serve dual purposes (typing text vs finding something), utilizing the more semantic type (`type="search"`) and pairing it with an `aria-label` guarantees that assistive technologies can immediately understand the element's purpose without visual context.
**Action:** When creating toggle buttons or filter buttons in Maud templates with associated JS, ensure `aria-pressed` or `aria-selected` is initialized statically in the `html!` block and kept in sync via Javascript alongside visual classes. When adding generic text inputs that function as search boxes, convert `type="text"` to `type="search"` and append an `aria-label` attribute if no explicit `<label>` element is present.
